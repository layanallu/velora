# Architecture

## Repository layout

```text
Velora/
├── Velora.xcodeproj/           # Open this in Xcode
├── Velora/                     # Xcode app target (file-system-synchronized)
│   ├── VeloraApp.swift
│   ├── RootView.swift
│   ├── Models/                   # TopicLibrary, session states and scoring models
│   ├── Core/
│   │   ├── Audio/               # Recognition, onset analysis, recording and playback
│   │   └── Persistence/         # Small local preferences
│   ├── UI/
│   │   ├── Component/           # Shared character, progress, karaoke and exit UI
│   │   └── Screens/             # Onboarding, Home, Topic, Ritual and Session
│   ├── Assets.xcassets/
│   └── LaunchScreen.storyboard
├── QualityChecks/              # Swift CLI checks; not part of app runtime
├── docs/
│   └── images/                 # README screenshots; not in the Xcode app target
├── README.md
├── CHANGELOG.md
└── .gitignore
```

The existing folder **`UI/Component` is intentionally left unchanged**. Renaming application source folders during release cleanup could change Xcode's synchronized build membership or invalidate resource references.

## Design and state flow

- `VeloraApp.swift` / `RootView.swift` establish the entry flow.
- Topic data and cumulative steps are generated by `Models/TopicLibrary.swift`.
- `BreathingGateView.swift` provides the pre-session timed breathing ritual and transitions into `ScenarioStartView.swift`.
- `SessionView.swift` orchestrates `EasyOnsetView.swift`, `RhythmPacingView.swift`, and `FeedbackView.swift`.
- `SessionExitOverlay.swift` is the shared confirmation surface; direct exit is never the effect of dismissing the overlay.
- `ProgressTimelineView.swift`, `VeloraCharacterView.swift`, `KaraokeTextView.swift` and `ParagraphPacingTextView.swift` compose the visual guidance.

## Offline speech and audio

- `SpeechTranscriber.swift` requests local recognition, runs Apple Speech/AVFoundation and provides recognition results.
- `SpeechWordMatcher.swift` normalizes simple textual variants before evaluating words.
- `OnsetAnalyzer.swift`, `OnsetEvidenceStore.swift` and `EasyOnsetAcceptance.swift` support the **heuristic** first-sound evidence and decision gate.
- Rhythm recordings are created locally by `AudioRecorder.swift` and replayed via `AudioPlayback.swift` in Feedback. The app includes two bundled example audio files for technique previews/demo behavior.

## Developer expectations

Preserve the same underlying sentences in Easy Onset and Rhythm, and do not substitute word recognition for a judgment on gentle onset. The current heuristic can yield uncertain results; it should not be advertised as a validated clinical measure. Keep audio processing offline and preserve the emotional safety of user-facing language.
